# Лабораторная работа №2

## Цель
Создать собственную командную оболочку, способную интерпретировать базовые команды для взаимодействия с операционной системой.

В папке [src](./src) лежат файлы с реализацией задачи заданной в лабораторной работе.

В файле [main.py](./src/main.py) описана точка входа в приложение - функция main. С запуском файла main ("python -m src.main") происходит запуск цикла, принимающего и обрабатывающего команды через терминал до тех пор, пока не будет введён символ остановки ("q").

В файле [shell.py](./src/shell.py) содежится реализация интерпретации полученных от пользователя строк и вызова соответствующих им функций.

В файле [commmand_execute.py](./src/commmand_execute.py) содежится реализация методов, вызываемых из shell.py и выполняющих задачи командной оболочки.

В папке [tests](./tests) лежат unit тесты для проверки функциональности программы или ее частей. В тестах содержатся проверки как успешных, так и error-кейсов. Подробнее о тестах - ниже.

В файле [constants.py](./src/constants.py) содержатся константы, необходимые для работы проекта. Константы, отвечающие за backup-директории, создаются по мере падобности в соответствии с расположением проекта в системе пользователя.

В журнале [shell.log](./src/shell.log) сохраняются логи основных рабочих функций (методов класса Shell, описанного в файле shell.py и класса CommandExecute, описанного в файле command_execute.py. Подробнее о них - ниже).

Формат логов:
- Получение ввода от пользователя: [YYYY-MM-DD HH:MM:MS] COMMAND: data
- Успешное исполнение введённой команды: [YYYY-MM-DD HH:MM:MS] SUCCESS: data
- Ошибка исполнения введённой команды: [YYYY-MM-DD HH:MM:MS] ERROR: data

## Логика работы [shell.py](./src/shell.py) и [command_execute.py](./src/command_execute.py)

- В файле shell.py описан класс Shell, содержащий методы интерпретации команд. Также при инициализации класса Shell создается объект класса CommandExecutor (описан в command_execute.py), содержащий методы исполнения команд.
- Метод parse_line класса Shell разбивает строку на команду, аргументы и опции, а затем вызывает соответствующий текущей команде ecexute-метод из класса CommandExecutor.
- Execute-методы описаны для каждой команды. Эти методы используют модули os и shutil для исполнения команд с заданными аргументами и опциями. Содержимое execute-методов обёрнуто в конструкции try-except, что позволяет в едином формате обрабатывать и выводить все ошибки, возникшие в ходе исполнения execute-методов, в терминал пользователю. Стоит отметить, что в except попадают как ошибки os/shutil, так и все кастомные ошибки методов. Сделано это для сохранения единого формата обработки всех ошибок. Кроме того, реализован класс ShellSyntaxError, необходимый для обработки ошибок ввода команд.

## Возможности командной оболочки:

### Перечень команд и правила ввода:

-  ls <path> - list directory contents\n
    -l: detailed view with size, date, permissions
-  cd <path> - change directory\n
    ~ - home directory\n
    .. - parent directory
-  cat <file> - display file content
-  cp <src> <dst> - copy files/directories\n
    -r: recursive copy for directories
-  mv <src> <dst> - move or rename files/directories
-  rm <path> - remove files/directories\n
    -r: recursive removal\n  requires confirmation
-  pwd - print working directory
-  touch <file> - create empty file or update timestamp
-  zip <source> <archive.zip> - create ZIP archive
-  unzip <archive.zip> - extract ZIP archive
-  tar <source> <archive.tar> - create TAR archive
-  untar <archive.tar> - extract TAR archive
-  grep <pattern> <path> - search text in files\n
    -r: recursive search\n
    -i: ignore case
-  history <N> (optional) - show command history (last N commands)
    -c: clear history
-  help - show all available commands with rules
-  undo - revert last cp/mv/rm/touch/cd operation

- Опция --help реализована для всех (кроме help) команд и выводит подсказки к их использованию.

Подробнее про undo:
- Undo возможен для следующих команд: touch, cd, cp, mv, rm.
- Для реализации undo создается специальный стек (атрибут класса Shell - command_stack), в котором хранятся введённые команды (из списка возможных для undo) и данные, необходимые для их отмены (для удобства команды сохраняются в виде объектов специального класса Command)
- Undo отменяет крайнюю команду из списка возможных, даже если после этой команды были выполнены другие (не поддерживающие undo).

Поддержка n-ого (увеличенного) количества аргументов:
- touch, rm, cp, mv - рассматривают каждый аргумент по отдельности (независимо друг от друга), выполняют действия со всем аргументами, с которыми это возможно. Команда с увеличенным количеством аргументов будет занесена в command_stack единой группой, т.е. при последующем undo произойдет отмена команды со всеми выполненнымм ранее аргументами (кроме тех, которые вызвали ошибки, и поэтому не были занесены в стек).

Backup-директории:
- Необходимы для восстановления перезаписанных/удалённых файлов и директорий.
- Файлы и директории хранятся в бэкап-директориях с измененными названиями (8-char uuid + original name). Это необходимо для избежания появления дубликатов по названиям.

## Логика работы [test_executes.py](./tests/test_executes.py) и [test_parsing.py](./tests/test_parsing.py)

- В файле test_executes.py с помощью модуля pyfakefs создается эмуляция файловой системы, в которой проводятся тесты различных методов класса Shell.
- Метод setUp() позволяет создавать изолированную файловую систему для каждого теста. Pyfakefs позволяет создавать файлы и папки в виртуальной памяти, изменяя соответствующие связи методов os/shutil.
- Файлы создаются и изменяются в виртуальной файловой системе, что позволяет оценить корректность работы execute-методов без реального создания файлов.
- В файле test_parsing.py проверяется, что метод parse_line верно разбивает исходную строку на команды, аргументы и опции.
- Моки используются для подмены ненужных в тестах функций и сосредоточения на конкретных частях функционала.
- Запустить тесты:
    "python -m unittest tests/test_executes.py"
    "pytest tests/test_parsing.py"
